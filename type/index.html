Engineering note

Four type techniques, zero dependencies

The constraint

Kinetic typography that survives a real content workflow — copy that changes, translations that run longer, and a client who will paste in a sentence twice the length of the one it was designed around.

Why the obvious route fails

Most kinetic type splits a headline into one DOM node per character and animates each. That breaks text selection, confuses screen readers, churns hundreds of nodes on every resize, and shatters the moment the copy changes length.

What I did instead

Reveals use real overflow masks on word wrappers, so letters are genuinely clipped by the line above the way a printed slug would be. The decode runs one requestAnimationFrame loop over a string — no per-character nodes at all. The inversion is mix-blend-mode: difference on a sticky headline: three declarations, and not one line of JavaScript touches it.

The trade-off I accepted

Difference blending needs a two-colour ground. It is exact over flat panels and turns to mud over photography, so it is a deliberate choice for a controlled palette rather than a general-purpose technique. The text is also readable before any script runs — JS arms the hidden state, never the reverse.
